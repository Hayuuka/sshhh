# sshhh 状态协议

描述 `scripts/sshhh.py` 与调用方（AI agent）之间的约定。

## 输出通道

| 通道 | 内容 |
|------|------|
| stdout | 远端命令的标准输出；配置类命令的人类可读提示 |
| stderr | 错误信息；状态标记行 `SSHHH_STATUS: <NAME>` |
| 退出码 | 远端命令的退出码，或下列保留码 |

## 保留退出码

| 码 | 名称 | 含义 | 建议动作 |
|----|------|------|----------|
| 0 | — | 成功 | 使用输出 |
| 2 | — | **参数格式错误** | 修正调用方式 |
| 3 | — | **配置/状态错误** | 读 stderr |
| 4 | — | 网络或认证失败 | 读 stderr，必要时 `test` |
| 10 | `CONFIGURED` | 用户刚完成初始化配置 | 重试原命令（一次） |
| 11 | `CANCELLED` | 用户在配置窗口取消 | 停止重试，告知用户 |
| 12 | `TIMEOUT` | 配置窗口等待超时 | 告知用户手动执行 hint 中的命令 |
| 13 | `LOCKED` | 密码库无法自动解锁 | 告知用户执行 `unlock` |
| 14 | `HOST_ADDED` | 用户刚添加了目标主机 | 重试原命令（一次） |
| 20 | `NO_RUNTIME` | venv 或依赖未就绪 | 告知用户执行 `setup` |

### 2 与 3 的边界

这两个码容易混，按「错误发生在哪一层」区分：

- **2 = 调用方式不对**，参数缺失、顺序错误、命令为空。重发一次正确的调用即可解决。
  - `sshhh run`（没给主机）
  - `sshhh run prod`（没给命令）
  - `sshhh put prod a`（少一个路径参数）
  - `sshhh --bogus-flag run prod x`（未知选项被当成主机名时同样归此类）

- **3 = 调用方式没问题，但当前状态做不到**。需要先改变状态。
  - `sshhh test ghost-host`（参数正确，但这台机器不在清单里）
  - `sshhh put ghost-host a b`（同上）
  - `sshhh unlock`（还没初始化，没有密码库）
  - 配置文件损坏、内部异常

注意：`sshhh run ghost-host "ls"` **不返回 3**，而是弹窗添加主机 → 14 或 11。
只有 `test` / `put` / `get` / `setpass` 这类明确指定主机的命令才会返回 3。

## 状态行格式

```
SSHHH_STATUS: CONFIGURED
SSHHH_MESSAGE: 已经完成初始化配置，请重试这条命令
SSHHH_HINT: 配置完成，直接重试原命令即可。
```

三行都可能出现，`SSHHH_STATUS` 一定在第一行。行内不含任何凭据。

## 歧义处理

远端命令本身可能返回 10-14 或 20，与保留码冲突。区分方式：

- **有 stdout 输出** → 是远端命令的结果，退出码按远端含义解释
- **stdout 为空且 stderr 有 `SSHHH_STATUS`** → 是协议状态

## 配置窗口的行为

| 触发条件 | 窗口任务 | 用户看到 | 成功 | 取消 |
|----------|----------|----------|------|------|
| `~/.sshhh/vault.enc` 不存在 | `setup` | 设主密码 + 加第一台服务器 | 10 | 11 |
| 密码库存在但主密码取不到 | `unlock` | 只输入主密码 | 继续执行 | 11 |
| 主机不在清单里，或该主机缺密码 | `add_host` | 填地址、用户名、端口、密码 | 14 | 11 |

窗口本身：

- 是真正的控制台（Windows `CREATE_NEW_CONSOLE`），`getpass` 能正常隐藏输入
- 默认最多等待 **180 秒**，可用 `SSHHH_SETUP_TIMEOUT` 调整
- 用户按 `Ctrl+C` → 窗口退出 → 结果文件为 `cancel` → 返回 11
- 用户点窗口右上角 X → 结果文件缺失 → 同样按取消处理
- 等待超时 → `taskkill /T /F` 结束窗口 → 返回 12

### 超时参数

`SSHHH_SETUP_TIMEOUT` 单位为秒，**默认 180，合法范围 30–600**。
超出范围、非数字、负数一律回落默认值 180，不会报错也不会无限等待。

注意：这个环境变量只影响**配置窗口**的等待时长，不影响并发锁的 30 秒上限。

### 与 agent 命令超时的关系

三层超时由内向外递增，保证内层总能先超时并返回状态码，外层还来得及处理：

```
pip 安装 150s  <  配置窗口 180s  <  建议首次调用 400s
```

- agent 的命令超时若 **< 150s**：pip 卡在网络上时 agent 会先被打断，
  用户看到的是「命令超时」而不是「安装依赖超时」，脚本里写好的提示永远发不出来
- agent 的命令超时若 **< 180s**：窗口还没等用户输完就被打断，拿不到 12
- 最坏情况（既要装依赖又要弹窗）约 330s，所以首次调用建议给 **400s**

日常调用（环境已就绪、密码库已解锁）1-2 秒返回，给 60 秒足够。

### NO_RUNTIME 的两种成因

| 成因 | 脚本能否自己发现 | hint 指向 |
|------|------------------|-----------|
| Python 版本低于 3.9 | 能 | 升级 Python |
| 依赖下载失败 / 超时 | 能 | 跑 `setup`，必要时换 `PIP_INDEX_URL` |
| **机器完全没装 Python** | **不能** | 脚本根本启动不了，由 agent 看到 `command not found` 后自行判断 |

最后一行是协议边界：脚本只能检测到「有 Python 但太旧」，检测不到「没有 Python」。
这种情况不会出现任何状态码，agent 需要根据 shell 报错自行引导用户。

## 并发与锁

多个 agent 可能同时触发配置（例如两个窗口同时收到「连一下服务器」）。

- `vault.enc` / `hosts.toml` 的所有写入都在 `~/.sshhh/.lock` 文件锁保护下串行执行
- 锁是非阻塞获取 + 重试，**单个写操作最多等待 30 秒**
- 超过 30 秒仍未拿到锁 → 返回 **3**（不是 12），stderr 提示
  「另一个 sshhh 进程正在配置，请稍后重试」
- 后到的 agent 会看到自己的调用短暂停顿（通常 < 1 秒），这是正常现象，
  不是卡死；只有持续超过 30 秒才需要提示用户
- 加锁范围只包含「读-改-写」这一小段，配置窗口等待用户输入的整个过程
  **不持有锁**，所以不会阻塞其他 agent 的只读操作（`list` / `run`）

### 三个超时不要混

协议里有三个独立的超时，量级相近但含义完全不同：

| 项目 | 上限 | 超时行为 | 能否调整 |
|------|------|----------|----------|
| 并发锁等待 | 30 秒（固定） | 返回 **3**，提示另一个进程正在配置 | 不能 |
| pip 安装依赖 | 150 秒（固定） | 返回 **20**，提示「安装依赖超时，网络可能不通」 | 不能 |
| 配置窗口等待 | 180 秒（默认） | 返回 **12**，让用户手动执行 `config` | 能，`SSHHH_SETUP_TIMEOUT` 30–600 |

一句话区分：

- 看到 **3** 且提到「另一个进程正在配置」→ 锁没抢到，稍后重试
- 看到 **20** 且提到超时/pip → 网络问题，让用户换源后跑 `setup`
- 看到 **12** → 用户没在窗口里及时输入，让他手动跑 `config`

## 回传文件的实现约束

配置窗口的结果通过一个临时 JSON 文件回传给父进程，父进程读完即删。

**该文件只允许出现三个字段：**

```json
{"status": "ok | cancel | error", "host": "主机名", "error": "错误摘要"}
```

硬约束（代码强制，不只是文档约定）：

- 写侧 `console_setup._write_result()` 用 `RESULT_KEYS` 白名单过滤，
  不在白名单的 key 一律丢弃
- 读侧 `console._read_result()` 用同一份白名单二次过滤，
  即使文件被人为改动也不会把多余字段带进来
- `status` 不合法时整体判为 `error`

也就是说，密码、主密码、密钥材料**在任何情况下都不会经由这个文件流转**。
修改这里时请同步更新两处白名单。

## 密码的流转

```
用户输入 (窗口进程内存)
        │
        ├─→ AES-GCM 加密 ─→ ~/.sshhh/vault.enc
        └─→ 主密码 ────────→ Windows 凭据管理器
                              │
agent 调用时 ─────────────────┘
        │
        └─→ 脚本取出明文 → paramiko.connect() → 用完即弃
```

明文不落盘、不进 argv、不进环境变量、不进日志、不回显。

## 数据目录

固定为 `~/.sshhh/`，与 skill 的安装位置无关。装多份 skill 副本也共用这一份数据。

| 文件 | 内容 |
|------|------|
| `vault.enc` | AES-GCM 加密的密码库 |
| `hosts.toml` | 主机清单，**无密码字段** |
| `audit.log` | JSONL 审计日志，命令写入前已脱敏 |
| `known_hosts` | TOFU 记录的主机指纹 |
| `.lock` | 跨进程文件锁 |
| `venv/` | 共享运行时（首次调用时创建，约 35 MB） |

环境变量 `SSHHH_DATA_DIR` 可覆盖此目录，**仅供测试隔离使用**。
