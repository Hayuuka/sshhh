## 0. 设计宪法（重构也不动摇的东西）

1. **凭据永不进入 agent 上下文** —— 由进程层保证（独立窗口输入、密文落盘、解密只发生在 sshhh 进程内），与分发形态（skill / MCP / CLI）正交。
2. **一次配置，全 agent 共用** —— 数据固定在 `~/.sshhh/`，与 skill 安装位置无关。
3. **skill 是主分发形态** —— 上下文经济学适配（平时仅一行元数据驻留，触发时加载正文，会话内复用）。MCP 是后续适配器，观察到 agent 误读协议的实际证据再启动。
4. **状态码协议是契约**（references/protocol.md）—— 只增不改；agent 面任何演进不得破坏现有判定规则。nonce 防伪造（#36）是增量扩展。
5. **诚实声明安全边界** —— 本地策略 ≠ 安全边界（是防手滑，#28）；同 UID 进程挡不住（OS 边界）；audit 同 UID 可篡改（记录不是阻止）。安全上限唯一由服务端强制（#15）决定；其余一切是纵深、留痕与封顶。

## 1. 三层架构（按「谁能改它」分层，不是按「代码在哪运行」）

```
A 执行层（agent 面）   run / put / get / test / list / status    —— 瘦客户端，无安全职责
B 防手滑层（本地）     策略 / 脱敏 / 审计 / 传输约束             —— 提高误用与手滑成本，非边界
C 边界层（服务端）     受限 authorized_keys + 服务端包装         —— 唯一 agent 无法绕过的强制
```

| 层 | 职责 | 定性 | 假设它失效时 |
|---|---|---|---|
| A | 参数打包、结果透传、状态码翻译 | 无安全职责 | 只是不可用 |
| B | 策略校验、脱敏、审计、路径约束 | **防手滑，非安全边界**（文件与代码对 agent 可写） | 退化为无策略，C 层仍在 |
| C | `command=` 限制、no-pty、no-forwarding、服务端侧日志 | **唯一真边界** | 本地 A/B 全被攻破时，损失仍被封顶 |

可选层 D（缓存，默认关闭）：daemon 提升速度，不提升安全上限（#14）。准入条件见 §6 P3 与附录 A。

### 产品两档（分发的现实约束）

sshhh 是分发给他人的开源工具，**默认体验不得依赖对用户服务器的任何改动**（服务器可能不是 OpenSSH、可能是受限账户、用户可能就是不想装）：

- **基线模式（默认，所有人）**：纯本地。凭据安全（密码不进上下文 / argv / 日志）**100% 在此档实现，与服务器无关**；行为限制为防手滑 + 留痕 + 封顶，如实标注。C 层是安全物理上的「唯一真边界」，但不是产品的前提。
- **加固模式（可选，`sshhh harden <主机>`）**：一键、幂等、可回滚（`--rollback`）、失败优雅降级（非 OpenSSH / 无 shell / 受限账户 → 留在基线档并说明原因）。只动用户自己在该服务器上的 home 目录（`authorized_keys`、`~/bin` 包装），不要求 root、不改 sshd_config——性质同 `ssh-copy-id`，不是替别人的服务器定政策。
- **当前决策（2026-11-09，作者）**：基线做到完善，加固**只开接口、点到为止**——接口三件套（审计 auth 字段、vault `key:<host>` 约定、`harden --check` 只读探测）在 P1 定型（#37）；完整写操作（装公钥、服务端包装、回滚）后置到观察名单，有真实需求或用户反馈再启动。
- **降级可观测**：连接优先用受限密钥，回落到 vault 密码时在审计与状态里留痕，防止加固被静默移除后无人察觉。

两档管的是不同的问题：**凭据安全（密码会不会漏）在基线档就完成**；加固档抬的是「agent 在服务器上能做什么」的上限。

## 2. 凭据生命周期（密码退役）

```
基线首跑（用户唯一的一分钟）：输主密码 + 服务器密码，或导入已有 ~/.ssh 密钥
  └─ sshhh 顺手完成：凭据入 vault（私钥同样以密文入 vault，见下）
日常：凭据按需解密使用（密钥优先于密码）；「密码退役到仅恢复用途」需加固档才达成
加固首跑（后置可选，见 §1 产品两档）：生成密钥对 → 装受限公钥 → 部署服务端包装 → 此后日常不再碰密码
恢复：密码出 vault 重新引导（服务器重装、密钥轮换）；恢复路径需文档化并演练，防备用凭据静默腐烂
```

两条硬性前置（评审 F6 / Q5）：

- **私钥只以密文存在 vault 内**（`key:<host>` 条目，与主密码同源派生），运行时从内存加载（`Ed25519Key.from_private_key(StringIO(pem))`），进程退出即消失。明文私钥落盘 = 把加密凭据降级成明文凭据，禁止。
- **`command=` 与 SFTP 子系统不可共存**：put/get 需改走 exec 通道（`cat >` / tar 流，由服务端包装按 `$SSH_ORIGINAL_COMMAND` 分派）或砍掉文件通道。这是 P2 的核心设计题，不是实现细节。

安全增益的核心逻辑：**密码是全权的，受限密钥不是**——密钥即使被偷，只够做服务端白名单允许的事。另注意 `key_file` 字段是托管旁路（#18），必须先封。

## 3. 防线重述（修订后）

| 防线 | 是什么 | 不是什么 |
|---|---|---|
| C 强制 | sshd 强制，agent 绕不过 | —— |
| B 防手滑 | 策略（fullmatch + 元字符默认拒，#28）、脱敏、传输路径约束（#32）、TOFU（#31） | 不是边界：hosts.toml / 代码对 agent 可写，#18 收窄这个口子 |

| 监管与封顶 | 首连指纹播报、输出/传输封顶（#24 #32）、（远期）限时授权 | 不是实时防护 |

## 4. 威胁模型（#35，P0.5 gate）

> P2/P3 任何 issue 开工前必须引用本节条目 ID（出口标准）。矩阵**只增不改**（同宪法 4 的精神）。
> 标「声明边界」的条目不承诺修复，只承诺如实告知用户——修改任何对外措辞前先对照这里。

### 4.1 资产

| 编号 | 资产 | 内容 |
|---|---|---|
| S1 | SSH 凭据 | 主密码、各主机密码、vault 密文、未来的私钥条目 |
| S2 | 本地数据目录完整性 | `hosts.toml` / `known_hosts` / `audit.log` / `venv` 不被改写 |
| S3 | 远端服务器完整性 | agent 在服务器上执行的操作符合用户意图 |
| S4 | agent 上下文 | 不被灌爆、不被残缺输出误导、不混入凭据 |

### 4.2 四类对手（A→C 能力递增，D 为正交方向）

| 对手 | 定义 | 能力上限 | 意图 |
|---|---|---|---|
| **A 手滑 agent** | 正常调用脚本的 agent，误操作 | 调用面（run / put / get / test / …） | 无辜 |
| **B 被引导 agent** | 被注入内容（远端输出、用户转述、网页）操纵的 agent | A 的全部 + 说服用户、写本地文件、直接调内部模块（极限下与 C 重合） | 被操纵 |
| **C 同 UID 进程** | 本机同操作系统用户的任意进程（被攻陷的 agent、其它 agent、恶意软件） | A/B 的全部 + 直接读写 `~/.sshhh/`、调用 `lib.*`、读系统凭据库 | 恶意 |
| **D 远端与网络** | 恶意/被攻陷的远端主机、中间人 | 控制远端输出与文件系统；网络层窃听与篡改 | 恶意 |

A 与 B 的区分是**意图与频率，不是能力**——B 极限下能做 C 能做的一切（写代码即等价）。
因此**对 B 的任何安全承诺都必须 ≤ 对 C 的承诺**：凡是「C 拦不住」的条目，对 B 同样拦不住。
本蓝图不为 B 设计任何针对「说服力」的防线（那是模型层问题）；B 只依赖与 C 相同的强制与留痕。

### 4.4 读法

- 「声明边界」≠ 不做事：这些条目由宪法 5 与 README / protocol 的如实声明覆盖，措辞改动先改这里。
- P2（密钥优先）直接服务 TM-B2 / C1 / C3 / D4：密码退役到仅恢复用途后，被偷的凭据从「全权」降为「白名单」。
- P3（daemon）**不改变任何对手的能力，矩阵不变**；附录 A 回答的是「加缓存是否降级既有承诺」。

## 附录 A：IPC 威胁模型（daemon，P3 准入）

定位重申：daemon 是可选缓存（默认关闭），不是安全层。本附录**不引入新对手**——能碰到 IPC 的对手全部已在 §4.2 内（TM-C 同 UID 进程 + TM-B 经由正规客户端发起的调用）。要回答的唯一问题：**加了缓存后，P2 已完成的承诺是否仍然成立；daemon 会不会成为 agent 面被诱导时的放大器。**

| ID | 威胁路径 | 定性 | 设计要求 | 对应矩阵条目 |
|---|---|---|---|---|
| IPC-1 | 管道名抢占（攻击者先创建同名管道等客户端来连，假 daemon 收请求） | 完整性/可用性，**不涉机密**（凭据不过 IPC） | daemon 启动时把身份写入 0600 文件（pid + 随机 session key）；客户端连接前凭此握手校验对端，失败即弃连并出状态码，**不回落明文通道** | TM-C3 同级：假结果 = agent 被骗，与远端输出被篡改同档 |
| IPC-2 | 未授权客户端调用 daemon | **daemon 不是门卫**（宪法 5）：同 UID 恶意进程不承诺拦住 | 不做调用方鉴权承诺；只保证「有 daemon 时策略语义与无 daemon 时完全一致」，策略判定对**每次请求**在 daemon 侧重跑 | TM-C1 / TM-C3；P3 出口标准的依据 |
| IPC-3 | 客户端篡改 `hosts.toml` 后调 daemon | 完整性 | 请求只允许携带主机名与命令，策略/路径一律由 daemon 从**自己持有**的 `hosts.toml` 解析；daemon 持句柄 + 内容基准，检测到外改即重载或拒绝 | TM-C3；与 IPC-2 组合即 P3 出口标准「携带被篡改 hosts.toml 的调用被拒绝」 |
| IPC-4 | 重放截获的合法 IPC 请求 | 完整性 / 审计保真 | 每请求 nonce + daemon 侧单调计数，重现即拒；重放必须在审计中可区分于真实发起 | TM-B 放大器防线 |
| IPC-5 | 跨用户访问管道 / socket | 机密性 | Windows：DACL 限定当前用户 SID（禁止 NULL DACL）；POSIX：Unix socket 0600 + peer creds 校验。**防的是其它用户，不防同用户**（如实声明） | TM-C 不在防护范围内（OS 边界） |
| IPC-6 | 启动方式与环境注入（PATH / env 劫持，`PIP_INDEX_URL` 类先例） | 完整性 | 绝对路径硬编码启动、不继承不可信 env、启动参数最小化；按需拉起 vs 用户手动启动由 P3 设计评审定 | TM-C5 |
| IPC-7 | daemon 常驻内存持有解密密钥 | 机密性（攻击面比按需解密宽：内存常驻、dump、窗口更宽） | 默认关闭（现状保持）；缓存条目带 TTL、空闲即清零；daemon 侧每次解密等同一次 `vault.open` 留痕 | TM-C1 / TM-C2 的 daemon 变体 |

**验收规则**：IPC-2 + IPC-3 组合即 P3 出口标准；IPC-1 / 4 / 5 / 6 / 7 在 P3 设计评审逐条对照。任何一条做不到，回答是「不做 daemon」（维持默认关闭），不是放宽标准。
